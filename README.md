# notmpc

A terminal MPD client drawn with [notcurses](https://notcurses.com): album
art in pixel graphics (kitty, sixel; character cells elsewhere), a braille
spectrum visualizer behind the header and a braille progress bar, and
rmpc's keys.

![notmpc in kitty: the queue grouped by album, the cover at full height,
the spectrum behind the header](docs/screenshot.webp)

<sub>Shown with colours taken from the terminal's palette (here generated by
noctalia from the wallpaper); see Configuration.</sub>

## Installing on Gentoo

The [notmpc-overlay](https://github.com/gtlaserbeast/notmpc-overlay) repo
has an ebuild (keyworded `~amd64`):

    eselect repository add notmpc-overlay git https://github.com/gtlaserbeast/notmpc-overlay.git
    emaint sync -r notmpc-overlay
    emerge --ask media-sound/notmpc

On a stable system, first add `media-sound/notmpc ~amd64` to
`/etc/portage/package.accept_keywords`.

## Building

Needs Rust ≥ 1.88, notcurses ≥ 3.0.8 built with its FFmpeg backend (for
album art), its headers, pkg-config, and clang (for bindgen). MPD ≥ 0.22.4
sends covers in large chunks; older servers work, just more slowly.

    cargo install --path .     # into ~/.cargo/bin; or: cargo build --release

## Connecting

Follows mpc: `MPD_HOST` (`[password@]host` or a socket path) and `MPD_PORT`.
Without them it tries `$XDG_RUNTIME_DIR/mpd/socket`, then `localhost:6600`.

**Playback follows the highlight** (foobar2000-style; `F` toggles). The
queue has two cursors:

- the *highlight* (the `cursor` colour) sits on the playing song and moves along
  with playback;
- the *browse cursor* (dotted `┆` rails, faint tint) is what j/k, gg/G, etc.
  move. Enter, d, Space, J/K, h/l act on it. It never affects playback.

`t` (PlayNext) moves the highlight to the browse cursor: that song plays
next, without cutting the current one short, and playback carries on from
there. Clicking a row does the same; double-click plays it now. `»` marks
the next song, the footer names it. Under the hood the playing song is
moved to just before the highlighted one (so MPD's transition stays
gapless) and back when the next song starts; the display always shows the
real order. Off in random or single mode. With following off, `t` moves
the song to play next instead.

## Directories

MPD's database as rmpc-style columns: parent, current folder, preview. The
preview shows the folder's cover (pixel graphics in kitty), album, year,
track count, length and format, and its contents; for a song, its tags.
Folders first, natural order (`Disc 2` before `Disc 10`); songs by disc and
track. The playing song and the folders containing it are highlighted.

| key            | action                                              |
|----------------|-----------------------------------------------------|
| j / k, gg / G  | move                                                |
| l / Enter      | open folder (Enter on a song: queue it and play)    |
| h              | up                                                  |
| a / A          | add selection / everything here to the end          |
| t              | play next (insert after the current song)           |
| Space          | mark (a / t then act on the marks)                  |
| C              | open the playing song's folder                      |

Mouse: click to select, double-click to open / play, click the left column
to go up, click an entry in the preview to open its folder. Adding starts
playback on the first new song if MPD is stopped (a paused song keeps
its place).

## Search

Type to search (live, case-insensitive substring). Words match any tag or
the file path; `field:value` narrows a word to one tag (artist, album,
albumartist, title, genre, date, composer, file); `"double quotes"` keep
spaces. Terms are ANDed: `artist:autechre album:"tri repetae"`.

Results are grouped by album (album artist, year, album, track). Copies of
one album in different folders stay separate, labelled with the folder.

| key                  | action                                         |
|----------------------|------------------------------------------------|
| typing               | edit the query (C-w word, C-u line)            |
| Enter / ↓ / Esc      | to the results (Enter searches immediately)    |
| i or /               | back to the query                              |
| Enter                | queue and play (an album header: the album)    |
| a / A                | add selection / all results                    |
| t                    | play next (insert after the current song)      |
| Space, h / l         | mark, collapse / expand album                  |

Mouse: click the query line to edit, a result to select, double-click to
queue and play, the ▾/▸ arrow to fold.

## Long titles

Text too long for its column ends in `…`, except on the highlighted row
and the browse cursor's row: there each cut field (title, artist, album,
the album header) scrolls through its full text, rests at its start for
a quarter second, and goes round again. Moving the cursor starts it over.
Set the speed with `marquee_speed` (cells per second, default 8; 0 keeps
the `…`). Nothing is redrawn while the text rests or when nothing is cut.

## Progress bar

`progress_bar` picks one of three (click anywhere on it to seek):

- `"braille"` (default): braille dots, moving in half-cell steps. A thick
  line behind the playhead, coloured in a gradient from `progress_elapsed`
  to `progress_thumb`; a thin `progress_track` line ahead; the playhead a
  tall tick in `progress_thumb`. Each second only the cell or two that
  changed are sent, so it's the cheapest.
- `"pixel"`: a thin rounded track drawn as an image, with a round thumb
  (terminals with pixel graphics: kitty, sixel; braille elsewhere). The
  image is re-sent once a second while playing.
- `"symbols"`: rmpc's bar from `progress_symbols`, in whole cells.

## Visualizer

A spectrum (one bar per column, 40 Hz–16 kHz, log-spaced) fills the
background of the header and progress bar; the text is drawn on a
transparent plane above it. It needs MPD's `fifo` output:

    audio_output {
            type    "fifo"
            name    "notmpc visualizer"
            path    "/run/user/1000/mpd/visualizer.fifo"
            format  "44100:16:2"
    }

notmpc reads `$XDG_RUNTIME_DIR/mpd/visualizer.fifo` by default
(`visualizer_fifo`), at 20 fps (`visualizer_fps`), over 3 rows
(`visualizer_rows`), two bars per column in braille dots. With
`visualizer_style = "blocks"` it's one bar per column in eighth blocks,
which colours whole cells (twice the bytes, the same CPU). It idles when
nothing plays. `V` hides / shows it
(saved); `visualizer = false` in the config turns it off from the start.

**Delay.** MPD writes the FIFO as it plays, but PipeWire buffers before the
speakers, so the bars would run ahead. notmpc timestamps the audio and
draws what arrived `visualizer_delay_ms` ago (default 150). Tune it by ear
with `[` / `]` (±10 ms); the value is saved to
`~/.local/state/notmpc/state.toml` and wins over the config. It stays put
unless PipeWire's quantum changes (another app asking for lower latency).

**Colours.** Each bar is one colour, taken from a gradient across the
spectrum (bass → treble), brighter the taller the bar. Pick a palette or
give your own stops:

    [theme]
    visualizer_colors = "aurora"   # aurora (default), ember, ocean, sunset, mono
    # visualizer_colors = ["#7b2ff7", "#2f80ed", "#12c2a0"]
    # visualizer_colors = ["2", "4"]   # terminal palette slots: follows the
    #                                  # terminal's theme (read at startup)

## Command line

    notmpc update [DIR] [--wait]   # scan for new / changed files (DIR: one folder)
    notmpc rescan [DIR] [--wait]   # same, re-reading unchanged files too
    notmpc albumart [FILE|-]       # save the playing song's cover
    notmpc config                  # print an example config with every setting
    notmpc --help / --version

`--wait` blocks until MPD has finished the scan. `albumart` writes the
embedded picture, or the folder's `cover.*`, as is (usually JPEG or PNG);
it exits 2 when there's no cover and 3 when nothing is playing. For
playback control, volume and the rest, `mpc` already does the job.

## Queueing from a file manager

    notmpc add PATH...      # append files / directory trees
    notmpc insert PATH...   # place them right after the current song

Directories are walked in natural order (`Disc 2` before `Disc 10`).
Files under MPD's music directory (symlinks resolved) are added by
database URI, others as `file://`. If MPD is stopped, the first new
song starts. For yazi:

    [[mgr.prepend_keymap]]
    on  = [ "m", "a" ]
    run = "shell 'notmpc add %s' --orphan"

If playback-follows-cursor has moved the playing song when an insert
arrives, the insert wins: the new songs play next.

## Configuration

`~/.config/notmpc/config.toml`, all optional; see `config.example.toml`.
The default keys are rmpc's (rmpc names and notation, so snippets carry
over). The default theme uses the terminal's palette, so it follows your
terminal's colour scheme, and only symbols any monospace font has.

## Keys

rmpc 0.11's defaults (`rmpc config`), including multi-key sequences; Search
is on 3 since the Artists/Albums/Playlists tabs don't exist, and keys for
actions notmpc doesn't have (command mode, rating, playlists, ...) are left
unbound. `/` jumps to Search from the other tabs. notmpc adds
`t` (play next), `F` (follow the highlight), `V` (visualizer on/off), `[` /
`]` (visualizer delay), `H`/`L` (collapse/expand all albums), `h`/`l` on the
queue (collapse/expand the album under the cursor), Home/End, and Del.

| key                          | action                                     |
|------------------------------|--------------------------------------------|
| 1 / 2 / 3, Tab / S-Tab, gt/gT | Queue / Directories / Search, cycle tabs  |
| p / s                        | play-pause / stop                          |
| > / <                        | next / previous                            |
| f / b                        | seek ±5s                                   |
| . / ,                        | volume ±5                                  |
| z x c v                      | repeat / random / consume / single         |
| F                            | playback follows cursor (see below)        |
| C-u / C-U                    | update / rescan (C-u is half-page in lists) |
| ?, oI, oi, oo, op            | help, playing / selected song info, outputs, decoders |
| q                            | quit                                       |
| j / k, ↓ / ↑                 | move                                       |
| C-d / C-u, C-f / C-b         | half page / page                           |
| gg / G                       | top / bottom                               |
| h / l                        | collapse / expand album                    |
| H / L                        | collapse / expand all albums               |
| Enter                        | play (an album header plays the album)     |
| Space / C-Space              | mark / invert marks                        |
| t                            | play next (moves the highlight here)       |
| d / D                        | delete / clear queue (asks first)          |
| J / K                        | move song down / up                        |
| C                            | jump to current song                       |
| X                            | shuffle                                    |
| Esc                          | clear marks                                |

**Panels** (`?` keys, `oI` / `oi` song info, `oo` outputs, `op` decoders)
open over a dimmed screen: j/k scroll, Enter or a click toggles an output,
Esc, q or a click outside closes. Song info lists every tag MPD has plus
extra tags from the file (ReplayGain, comments...). Covers hide while a
panel is open (pixel graphics can't sit under text).

On the queue tab, `▸ collapse all` / `▾ expand all` at the right of the tab
bar folds every album (keys `H` / `L`). The cover column is as wide as a
square cover needs to fill the height, up to `art_width` percent of the
width (60 by default).

Mouse: click a tab, a queue row (double-click plays; on an album header,
plays the album), an album's ▾/▸ arrow (collapses / expands it), a mode word
in the header (toggles it), or the progress bar (seeks there); the wheel
scrolls the view (the cursor stays put; the next key brings it back), or
changes volume over the volume ramp.

Untagged files show artist, album, year, and title guessed from the path,
in italics.

## Layout

- `build.rs` generates bindings from the system notcurses headers. The
  `libnotcurses-sys` crate wants notcurses ≥ 3.0.11, newer than Gentoo ships.
  `wrap_static_fns` turns notcurses' `static inline` API into linkable shims.
- `src/nc/` is a thin safe wrapper over the calls we use; `nc::sys` is raw.
- `src/mpd.rs` is a small blocking protocol client. The UI's connection
  gives up on a reply after 10 s; a second connection sits in `idle` on its
  own thread and tells the UI loop which subsystems changed.
- `src/main.rs` runs the loop. It sleeps until something on screen is due
  to change (the clock's next second, a visualizer frame, a pending search),
  and visualizer-only frames redraw just the visualizer.
- `src/config.rs` / `src/keys.rs`: config file, theme, rmpc-style keymap.
- `src/meta.rs`: display metadata, inferred from the path for untagged files.
- `src/app.rs` holds state and actions, `src/ui.rs` draws; `src/overlay.rs`
  is the panels (help, song info, outputs, decoders).
- `src/queue.rs`: a song list as shown (album groups, folding, cursor,
  marks), for the queue and search results, plus follow mode's moves.
- `src/browser.rs` (Directories), `src/search.rs` (Search).
- `src/enqueue.rs`: adding songs, shared by the UI and `src/cli.rs` (the
  command line).
- `src/art.rs` fetches covers (`readpicture`, then `albumart`), decodes
  them with notcurses' ffmpeg backend, and blits them onto their own planes:
  pixel graphics when the terminal supports them, half-blocks otherwise.
- `src/viz.rs`: the spectrum analyser (FIFO reader thread, FFT, bands).
- `src/pixelbar.rs`: the optional pixel progress bar.
- `src/marquee.rs`: scrolling for cut text on highlighted rows.

`cargo test` runs the unit tests. `tests/terminal/` has end-to-end tests
